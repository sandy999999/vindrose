# Vindrose v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the six static weather loops with four physical weather voices, two generated musical voices and a director that composes 8 to 10 minute pieces from the place and the reading.

**Architecture:** Pure domain modules (place profile, material spec, director) decide everything; the audio engine renders those decisions through one voice per channel and crossfades a whole new voice set when the place changes. The Session owns the piece clock and the director tick, and it multiplies every channel target by the section mask before handing it to the engine. The UI reads levels and the current section from the Session.

**Tech Stack:** Svelte 5 runes, TypeScript strict (`noUncheckedIndexedAccess`), Vite, Vitest, Web Audio API, maplibre-gl. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-29-vindrose-v2-sound-design.md`

## Global Constraints

- Seed is FNV-1a 32-bit of `` `${lat.toFixed(3)},${lon.toFixed(3)}` ``, unsigned.
- Tempo is `48 + (seed % 17)` BPM, fixed per place and piece.
- Aperture is `0.002 + (seed % 5) * 0.001` metres. Wind frequency is `0.2 * speed / aperture`, clamped to 80 to 2000 Hz.
- Mode by absolute latitude: below 23.5 Lydian, 23.5 to 45 Dorian, 45 to 60 Aeolian, 60 and up Phrygian. The root is always D (`midi 38`).
- Piece length is drawn from the seed in 480 to 600 seconds. Five sections at 510 s and above, four below.
- Storm score is `0.45*(gust/25) + 0.3*(speed/20) + 0.25*(precip/8)`, clamped to 0 to 1, plus 0.2 when the weather code is 80 or above, clamped again; a null reading scores 0.5.
- Section weights: emerge 1.0, build 1.2, expose 1.0, break 0.45, return 1.0. Ranges: emerge and return 90 to 150 s, build 120 to 180 s, expose 90 to 150 s, break 45 to 75 s.
- Channel level is mask x weather target x user gain. Masks multiply; a mask of 0 silences the channel at any fader value.
- The recording cap stays 600 s, the warning stays at 480 s, and the file name is `vindrose-<place-slug>-<yyyymmdd-hhmm>-<seed8>.wav` where seed8 is the 8-digit lowercase hex seed.
- `npm test` and `npm run check` are green at the end of every task. Tests use no network.

## Review Focus

1. A stored v1 mix with the old six channel ids opens without a crash and keeps every gain.
2. A slow or failing elevation lookup never changes the rain bus under a running piece.
3. A 20 minute pause then play continues the same piece at the same section, with no timer storm.
4. Weather code 95 with calm wind does not force a build the weather cannot fill.
5. Five place taps in two seconds leaves exactly one voice set running, the last place's.

- [ ] **Step 3: Implement `director.ts`**

`pieceLength = 480 + (seed % 121)`.

`stormScore`: the formula from Global Constraints; `null` returns 0.5 before any other work; clamp after each addition.

`planFor`:
1. `lengthSec = pieceLength(seed)`; `five = lengthSec >= 510`.
2. Kinds: five → `['emerge','build','expose','break','return']`; four → `['emerge', middle, 'break', 'return']` where middle comes from the score (`> 0.6` build, `< 0.2` emerge, else expose).
3. Split `lengthSec` by the weights, in order: `raw[i] = lengthSec * weight / totalWeight`, each rounded to whole seconds, and the last section takes `lengthSec - sum(previous)`. This keeps the sum exact.
4. Guard: if a part falls outside its range, move the difference into emerge, then return, taking from whichever neighbour has room. In practice the weights never need it; the guard is two lines and must not change the common path.
5. `solo` is set by Task 3; leave `solo: 'wind'` for now.

- [ ] **Step 3: Implement**

`soloVoice`: normalise `gust/25`, `speed/20`, `precip/8`, `|pressure - 1013|/20`, thunder 1 if code >= 95; pick the max, ties and null go to wind.

`layerMask`: a table with these starting values (tunable by ear later): emerge `{ wind 1, rain 0.6, gust 0.4, pressure 0.8, thunder 0, pad 0.5, motif 0 }`; build `{ wind 1, rain 1, gust 1, pressure 1, thunder 1, pad 1, motif 0.6 }`; expose `{ all 0, [solo] 1, motif 0.3 }`; break `{ wind 0.2, pad 0.15, rest 0 }`; return `{ wind 0.8, rain 0.8, gust 0.5, pressure 0.6, thunder 0, pad 0.7, motif 0.4 }`.

`bellAt`: `break.endSec - 2`.

`thunderSlots`: only when code >= 95. For each build and expose section, start at `startSec + 12` and step 90 s while `< endSec - 5`. Deterministic and ordered.

`nextSeed`: `fnv1a(\`${seed}:${pieceIndex}\`)`.

- `tick()` is called from the engine's bar handler and from `apply()`: computes the section, sets `state.section` on change, applies `mapWeather(...)` multiplied by `maskAt(plan, elapsed)`, sets `state.levels` to the masked target levels, and fires `bell` / `thunder-crack` when the clock crosses `bellAt` / the next `thunderSlots` value, each once. Past `plan.lengthSec` it calls `beginPiece()` again, with the next seed and `engine.setProfile(profile, 20)` for the 20 s chained fade; `beginPiece` resets the clock to now.
- `selectPlace`: bump `requestId` at the top and, after any await, return without touching state if a later call has superseded it, so two quick taps settle on the last place. It builds the profile with any cached elevation, saves it, sets state, and if a piece exists starts a new one at once; if playing, calls `engine.setProfile(profile, 4)`; if not playing, the next play does it.
- `deps.elevation` is fired without await; results cache in `private elevationCache = new Map<string, number | null>()` keyed by `${lat.toFixed(3)},${lon.toFixed(3)}`, so a place is looked up once per session. On success, recompute the profile; if no piece is running apply it, otherwise store it as `pendingProfile` and use it in the next `beginPiece()`.
- `live.ts`'s DeferredEngine gets the new methods (`setProfile`, `setTempo`) as deferred no-ops.
